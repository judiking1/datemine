# datemine — Product Spec (v0)

## 한 줄 정의
매일 아침 30초, "오늘이 무슨 날이고 어떤 발언·행동이 지뢰인지"를 확인하는
경각심 캘린더 앱. 운세 앱 포맷 + 사회적 리스크 브리핑.

## 타겟
- 인플루언서·유튜버·마케터·홍보/커뮤니케이션 담당
- SNS 발언 리스크를 신경 쓰는 일반 사용자

## 핵심 가치
- **매일** 다른 콘텐츠(습관화) + 직설적·실용적 경고(경각심)
- "매년 반복되는 실패 패턴"을 미리 알려주는 지뢰밭 지도

## 톤 정책 (제품 정체성 — 순화하지 말 것)
직설적이고 자극적인 경고가 이 앱의 **핵심 정체성**이다. 부드럽게 돌려 말하면
정작 사고 치는 사람은 의미를 못 알아듣는다. 그래서 발행 카피는 세게 간다.

- 예: "오늘 광복절. 매년 이맘때 **가문·조상 자랑**하다 친일 이력 털린 사람 나온다.
  오늘만큼은 집안 미화 접어라."
- 예: "오늘은 ○○의 날. 이 시기 **이런 발언**했다가 커리어 날아간 사례 반복됨."
- 순화 금지 / 개인 실명 노출 금지 — 이 둘은 동시에 지킨다 (아래 데이터 2층 구조).

## 데이터 2층 구조 (이 앱의 핵심 설계)

**Layer 1 — 연구 원본 (Raw, 내부 전용, 실명 포함 OK)**
- 뉴스 검색으로 "언제 / 누가 / 무엇을 잘못해서 / 무슨 일이 났는지"를 실명 포함해
  다 모은다. 이건 패턴을 도출하기 위한 **원재료**다.
- 하드 규칙: 이 레이어는 **내부 전용**이다. 클라이언트 번들·공개 API·발행 콘텐츠에
  절대 실리지 않는다. 접근 통제(비공개 DB/스토리지)하에만 존재한다.
- 개인정보보호법 준수: 공개된 보도 사실만 수집, 최소 보관, 목적 외 사용 금지.

**Layer 2 — 발행 콘텐츠 (Published, 실명 제거, 워딩은 세게)**
- Layer 1을 정리해 **실명·식별정보만 빼고** 자극적 경고 카피로 가공한다.
- 게시 전 **사람 검수 게이트**: 개인 특정 가능성·낙인 표현 제거, 사실 근거 확인.
- 사용자에게 노출되는 건 오직 이 레이어뿐이다.

> 요약: **수집은 실명까지 다 → 발행은 실명 빼고 세게.** "누가"는 내부에서 패턴을
> 만드는 데만 쓰고, 밖으로 나가는 건 "무슨 일이 반복되는가"다.

## 데이터 모델
```
DailyContext {                      // Layer 2 (발행)
  date, lunar/solar,
  dayType: 공휴일 | 기념일 | 추모일 | 선거 | 절기 | 평일,
  significance: 이 날의 의미(교육적),
  riskPatterns: [{ pattern, whyItBackfires, exampleSummary(실명제거), severity }],
  advice: 오늘의 자제 카피(세게)
}

RawCaseRecord {                     // Layer 1 (내부 전용, 절대 미발행)
  date, who, what, consequence, sources[]   // 실명·출처 포함
}
```
- 백본 A(고정): 한국 달력 **전체 날짜** × 의미. 공휴일뿐 아니라 절기(초복·중복·하지·
  입춘 등)·기념일까지 포함해 **모든 날에 콘텐츠**가 있게 한다. 1회 구축 후 매년 재사용.
- 백본 B(수집→발행): 뉴스 검색(Layer 1, 실명 포함) → 유형화 → 실명 제거·검수 →
  Layer 2 축적.

## 매일 콘텐츠 보장 규칙
- 사건·사고가 뚜렷한 날: 해당 이슈 유형으로 경고.
- 그런 게 없는 날: 그날의 **절기·전통 달력 의미**(초복·하지·입춘 등)를 기점으로,
  그 날짜 전후에 실제 있었던 이슈를 검색해 조심 포인트를 뽑는다.
- "특별한 날 아님"으로 비워두지 않는다 — 매일 최소 한 줄은 나온다.

## 기술 스택 (근본·안정·유지보수)
- 모노레포: pnpm workspaces + Turborepo, TypeScript 전면
- 앱: React Native + TypeScript (단일 코드베이스)
- 백엔드: Node + Hono(또는 NestJS), PostgreSQL, Drizzle/Prisma
- 공유 도메인 패키지: 앱·백엔드가 같은 타입 공유
- 콘텐츠 파이프라인: 검색 → LLM 유형화 → 사람 검수 → DB 커밋
- 아키텍처 원칙: 데이터 = source of truth, UI/알림은 파생 consumer

## MVP 스코프 (1차)
1. 한국 달력 백본 A: 공휴일·기념일·추모일 + **절기**까지 포함, 모든 날 커버
2. 발행 카드(Layer 2) 큐레이션 — 세게, 실명 없이
3. 오늘 날짜 매칭 → 카드 노출(사건 없는 날은 절기 기반 조심 포인트)
4. 아침 푸시 알림
5. 카드 공유(바이럴 훅)

## 로드맵
- P0: 모노레포 뼈대 + 백본 A 스키마(절기 포함 전체 달력)
- P1: 앱 MVP(오늘 카드, 매일 콘텐츠 보장) + 알림
- P2: 수집→발행 파이프라인 — Layer 1(내부 실명 수집) / Layer 2(실명제거·검수 발행) 분리 구현
- P3: 음력·지역 이벤트 확장, 개인화
